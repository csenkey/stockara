# Stockara Web UI User Manual

Audience: Stockara reviewers and web UI users.

Status: current Phase 1 implementation.

## What the web UI does today

The current Stockara UI is a public, static-artifact dashboard. It does not require login. It displays the latest daily publication generated by the Phase 1 pipeline and a data freshness view that explains whether the underlying collection process is healthy.

The UI has two main views:

- Stockara Daily Top Picks.
- Stockara Data Freshness.

## Navigation

The app uses simple hash navigation:

- Default route or `#`: Daily Top Picks.
- `#data-health`: Data Freshness.

Each view has a navigation button to switch to the other view and a Refresh button to reload the static JSON artifacts without a browser cache.

## Daily Top Picks view

The Daily Top Picks page loads:

- `/top-picks/latest.json`, unless `VITE_TOP_PICKS_URL` overrides it at build time.

Top summary metrics:

- Generated: timestamp of the latest publication.
- Top Picks: number of published BUY recommendations.
- Sell Alerts: number of urgent sell alerts.
- Analyzed: analyzed candidate count over candidate count.

## Reading a top pick

Each top-pick card represents a BUY recommendation that passed Stockara's publication gates.

Fields shown:

- Rank.
- Ticker.
- Company name.
- Sector.
- Recommendation badge.
- Risk level badge.
- Catalyst.
- Rationale.
- Static price chart.
- Confidence score.
- Expected timeframe.
- Supporting evidence.

How to interpret it:

- Rank is relative to the current publication only.
- Catalyst is the concise reason the candidate rose to the top.
- Rationale is the AI analyst's short thesis after scoring evidence.
- Confidence is a model output and review-adjusted value, not a probability of profit.
- Risk level is LOW, MEDIUM, or HIGH.
- Expected timeframe is the suggested thesis window, often near-term.
- Supporting evidence lists the strongest evidence snippets used by the analysis.

## Reading an urgent sell alert

Sell alerts appear below Top Picks. They are styled separately and represent high-severity negative signals for watched tickers or AI-generated SELL recommendations that passed review.

Fields shown:

- Rank.
- Ticker.
- Company name.
- Sector.
- Severity.
- Negative catalyst.
- Rationale.
- Static price chart.
- Confidence score.
- Risk level.
- Supporting evidence.

How to interpret it:

- Sell alerts are risk warnings, not personalized advice.
- A sell alert is included only when negative score and publication policy thresholds are met.
- Severity is currently high or critical.
- The chart helps reviewers inspect recent price behavior around the alert.

## Static price chart

Published picks and alerts may include a static OHLCV chart. The chart is rendered in the browser from JSON embedded in the publication artifact.

Chart elements:

- Candles: recent open/high/low/close sessions.
- Volume bars.
- SMA20 line.
- Trend line.
- Support line.
- Resistance line.
- Latest close, period return, support value, and trend slope.

If the publication does not contain enough chart data, the UI shows that the static price chart is unavailable for that card.

## Data warnings

The Daily Top Picks page may show a Data Warnings section.

Warnings can include:

- Partial universe coverage.
- Stale news collection.
- Fallback analysis use.
- Fallback actionable recommendations withheld from publication.
- AI recommendations withheld by the stronger review model.
- Freshness exclusion counts.

These warnings are important. They describe the scope and reliability of the current publication.

## Withheld AI Recommendations

When the analysis model proposes a BUY or SELL but the stronger review model rejects it, the UI shows it under Withheld AI Recommendations.

Each withheld card shows:

- Proposed recommendation.
- Ticker, company, and sector.
- Risk.
- Confidence.
- Opportunity score.
- Negative score.
- Analyst thesis.
- Reviewer rationale.
- Rejection category when available.
- What evidence would make it approvable when available.
- Review concerns.

This section is designed for transparency. It lets expert reviewers inspect where the system almost published an actionable recommendation but chose not to.

## Data Freshness view

The Data Freshness page loads three artifacts:

- `/data-health/latest.json`, unless `VITE_DATA_HEALTH_URL` overrides it.
- `/data-readiness/latest.json`, unless `VITE_DATA_READINESS_URL` overrides it.
- `/news/latest.json`, unless `VITE_NEWS_HEALTH_URL` overrides it.
- `/price-gaps/latest.json`, unless `VITE_PRICE_GAPS_URL` overrides it.

Top summary metrics:

- Manifest: manifest date.
- Active tickers: active watchlist size.
- News articles: recent article count.
- Price gap tickers: number of tickers with missing price ranges.

If an artifact is missing, the UI shows a missing static artifact warning.

## Collection Coverage Targets

This section explains whether the daily collection manifest is meeting its coverage goals.

Each gate card shows:

- Gate name.
- Status: on target or below target.
- Message.
- Observed value.
- Required value.
- Unit.

Use this section to judge whether the day's publication rests on enough current data.

## Manifest Tasks

The Manifest Tasks section summarizes work by task type. It shows counts such as:

- Total.
- Succeeded.
- Pending.
- Failed.

If tasks failed, a table lists up to 20 failures with task ID, type, ticker range, and failure reason.

## News Coverage

The News Coverage section summarizes recent news collection.

It shows:

- Lookback window.
- Update time.
- Articles processed from fetched articles.
- Available sources over total expected sources.
- Tickers with news.
- Duplicate count.
- Per-ticker news cards with article count and recent article titles.

Use this section to understand whether recent market sentiment inputs are present.

## Ticker Price Gaps

The Price Gaps section shows missing OHLCV coverage over the scanner window.

It shows:

- Scan start and end dates.
- Update time.
- Total missing trading days.
- Tickers with gaps.
- Per-ticker gap counts and missing trading days.
- Gap task IDs and statuses.

Use this section to identify whether a stock's price history may be incomplete.

## Refresh behavior

The Refresh button reloads the JSON artifact with `cache: no-store`. It does not trigger a backend job. If a publication or health artifact has not been generated yet, refreshing will continue to show the missing-artifact or waiting state until the scheduled pipeline publishes data.

## Current limitations

The current UI does not yet include the broader authenticated product features described in the product specs:

- User registration and login.
- Encrypted user portfolio management.
- Personalized portfolio suggestions.
- User preference settings.
- Demo-trading leaderboard and account detail pages.

Those features are part of the broader product direction, but the current deployed Phase 1 UI is focused on public top picks, sell alerts, withheld recommendation transparency, and data freshness.

## Reviewer checklist

When reviewing a daily publication:

- Confirm the Generated timestamp is current.
- Check the Analyzed and Candidate counts.
- Read Data Warnings before interpreting picks.
- Review Top Picks for catalyst specificity and supporting evidence quality.
- Review Sell Alerts for severity and negative catalyst quality.
- Inspect static charts for obvious contradictions or missing context.
- Open Data Freshness and confirm coverage gates are on target.
- Check News Coverage for source availability and ticker coverage.
- Check Price Gaps for missing data in tickers being discussed.
- Inspect Withheld AI Recommendations to understand rejected borderline ideas.
